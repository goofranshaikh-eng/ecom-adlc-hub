## Schemas and API Contracts

### Catalog Service

**Database:** `catalog_db`

**Collection:** `products`

```json
{
  "_id": "ObjectId",
  "name": "string",
  "price_minor_units": "integer",
  "sellable": "boolean"
}
```

**API:**

- `GET /products/search?q={query}` → `[{id, name, price_minor_units, sellable}, ...]`
- `GET /products/{product_id}` → `{id, name, price_minor_units, sellable}`
- `GET /docs` → Swagger UI

**Contract:** Returns product name, price (minor units), and sellable flag. Other services read this via HTTP; catalog owns the data.

---

### Cart Service

**Database:** `cart_db`

**Collection:** `carts`

```json
{
  "_id": "string (cart_id)",
  "lines": [
    {
      "product_id": "string",
      "quantity": "integer",
      "price_snapshot_minor_units": "integer"
    }
  ],
  "total_minor_units": "integer"
}
```

**API:**

- `POST /cart` → `{cart_id}`
- `GET /cart/{cart_id}` → `{cart_id, lines, total_minor_units}`
- `POST /cart/{cart_id}/items` body `{product_id, quantity}` → `{cart_id, lines, total_minor_units}`
  - **Contract with Catalog:** Calls `GET /products/{product_id}` to verify `sellable` and fetch current price. Rejects if `sellable: false` with `{error: "Product cannot be added", reason: "..."}`.
- `PATCH /cart/{cart_id}/items/{product_id}` body `{quantity}` → `{cart_id, lines, total_minor_units}`
  - Removes line when quantity is zero.
- `DELETE /cart/{cart_id}` → `204 No Content`
- `GET /docs` → Swagger UI

**Contract:** Cart total is sum of `price_snapshot_minor_units * quantity`. No direct database access to catalog; all price/sellability checks via HTTP.

### Identity Service

**Database:** `identity_db`

**Collection:** `shoppers`

```json
{
  "_id": "ObjectId (shopper_id)",
  "email": "string",
  "password_hash": "string"
}
```

**API:**

- `POST /sign-in` body `{email, password}` → `{shopper_id, token}` (token may be a stub in v1)
- `GET /shoppers/{shopper_id}` → `{shopper_id, email}`
- `GET /docs` → Swagger UI

**Contract:** Provides shopper ID for signed-in users. Checkout and order reference this ID; identity owns the account data.

---

### Checkout Service

**Database:** `checkout_db` (may be empty; checkout is stateless or logs idempotency keys)

**API:**

- `POST /checkout` body `{cart_id, shopper_id?, email?, ship_to?}` → `{order_id, status}` or `{error, reason}`
  1. **Contract with Cart:** Calls `GET /cart/{cart_id}` to get `total_minor_units` and `lines`.
  2. **Contract with Payment:** Calls `POST /payment/charge` with `{amount_minor_units: cart.total_minor_units}`.
  3. **If payment accepted:**
     - **Contract with Order:** Calls `POST /orders` with `{shopper_id?, email?, ship_to, lines, total_minor_units, payment_reference}`.
     - **Contract with Cart:** Calls `DELETE /cart/{cart_id}` to empty the cart.
     - Returns `{order_id, status: "paid"}`.
  4. **If payment refused:**
     - Returns `{status: "refused", reason: payment.reason}`. Cart remains unchanged.
- `GET /docs` → Swagger UI

**Contract:** Orchestrates cart → payment → order flow. Never accesses another service's database directly.

### Payment Service (Test Double)

**Database:** `payment_db`

**Collection:** `charges`

```json
{
  "_id": "ObjectId",
  "amount_minor_units": "integer",
  "status": "accepted | refused",
  "reference": "string (UUID or stub)",
  "reason": "string (only when refused)",
  "timestamp": "ISODate"
}
```

**API:**

- `POST /charge` body `{amount_minor_units, card?}` → `{status: "accepted", reference}` or `{status: "refused", reason}`
  - **Test double logic:** Accept if `amount_minor_units < 100000` and card number (if provided) does not end in `"0000"`; refuse otherwise.
- `GET /docs` → Swagger UI

**Contract:** Deterministic accept/refuse for testing. Returns `accepted` with a reference, or `refused` with a reason.

### Order Service

**Database:** `order_db`

**Collection:** `orders`

```json
{
  "_id": "ObjectId (order_id)",
  "shopper_id": "string (optional)",
  "email": "string (required for guest)",
  "ship_to": {
    "street": "string",
    "city": "string",
    "postal_code": "string",
    "country": "string"
  },
  "lines": [
    {
      "product_id": "string",
      "quantity": "integer",
      "price_minor_units": "integer"
    }
  ],
  "total_minor_units": "integer",
  "payment_reference": "string",
  "created_at": "ISODate"
}
```

**API:**

- `POST /orders` body `{shopper_id?, email?, ship_to, lines, total_minor_units, payment_reference}` → `{order_id}`
- `GET /orders/{order_id}` → `{order_id, shopper_id?, email?, ship_to, lines, total_minor_units, payment_reference, created_at}`
- `GET /docs` → Swagger UI (via `swagger-ui-express` or equivalent in Node.js)

**Contract:** Stores the final paid order. Never accesses another service's database.

## Risks

| Risk | Impact | Mitigation |
|------|--------|----------|
| **Price drift** | Catalog price changes between cart view and checkout; client sees one price, pays another. | Cart snapshots price at add-time. Checkout sends the cart total without recalculating. Deferred: price-lock or re-verification before charge. |
| **Network failure in checkout orchestration** | Payment succeeds but order not created, or order created but cart not emptied. | Deferred: idempotency keys and retry logic. V1 accepts this as a known gap. Mark in code with `[KNOWN_GAP]`. |
| **Concurrent cart updates** | Race condition when two requests modify the same cart simultaneously. | Deferred: optimistic locking or cart versioning. V1 uses last-write-wins. |
| **Payment test double too simplistic** | Tests pass but real provider integration would fail. | Accepted for v1. Mark payment logic with `[TEST_DOUBLE]` in code. Future: add realistic failure scenarios (timeout, partial charge). |
| **No authentication/authorization** | Any client can access any cart, order, or shopper data. | Deferred. V1 trusts the caller. Mark all endpoints as "public, no auth" in Swagger docs. |
| **No database transaction support** | MongoDB operations across services are not atomic; partial state possible. | Accepted for v1. Document in code where atomicity would matter (checkout → payment → order → cart). Future: consider sagas or 2PC. |
| **Unsellable product added to cart before sellability check** | Race: product becomes unsellable between fetch and add. | Cart calls catalog on every add; if catalog returns `sellable: false`, add is rejected. No lock on catalog. Deferred: inventory reservation. |
| **Cart total diverges from catalog price** | Catalog price changes after cart line is added. | Cart stores `price_snapshot_minor_units` at add-time and never recalculates. Checkout uses the cart total as-is. Deferred: detect drift and warn user. |
